# DeepSeek V4.1 Flash on SM120

The W4A8 PD configuration uses TP1/DP8/EP8 Prefill on one eight-GPU node
and TP1/DP16/EP16 Decode across two eight-GPU nodes. Use the normal
disaggregated serving entry points and configure the communication backend
on both roles. For deployment examples and prior results on the source
branch, see the [6000D benchmark recipes][recipes].

## Support scope

| Area | Change |
| --- | --- |
| Checkpoint and runtime | Load the SM120 W4A8 checkpoint, keep MXFP4 Engram storage packed on the host, and preserve DeepSeek V4.1 cache and multimodal row handling. |
| Prefill | Use eligible paged attention and optionally enable native FP4 indexing and FlashInfer routed MegaMoE. The MoE transport is Elastic unless the MegaMoE row bound is enabled. |
| Decode | Enable Elastic expert communication and optionally select the mixed-cache MLA kernel, including verified wider query buckets with CUDA Graphs. |
| PD handoff | Use the existing native SMG and Mooncake protocol. Paged-cache ownership and mapping checks apply before dispatch. |

The measurements below use the DeepSeek V4.1 Flash 1017 W4A8 checkpoint,
SM120a builds of the TokenSpeed kernels, FlashInfer 0.7.5, TokenSpeed
Triton/Proton 3.9.10.post20261028, and the Rust engine and Python client built
from the same source revision. The native 1P1D smoke and quality tests also used
SMG 1.16.0.post20261121. The SM120 DeepGEMM build is needed for the native FP4
Indexer. MegaMoE uses FlashInfer GIN and its runtime dependencies on the
Prefill worker.

## Rows and communication

QCP splits extend rows with the current per-request zigzag plan. A gather
returns rank-major rows; consumers indexed by original image spans or token
positions restore span order with `QueryShardPlan.to_span_order`. Model and
image-mask inputs select `local_row_ids`. Cached local row tensors live for
one metadata invocation and are invalidated on refresh.

Normal engines may use QCP for independent Prefill measurements. Pure Decode
rounds carry replicated rows and no query shard. Mixed sharded extend and
replicated Decode in one forward remain unsupported. With sharded KV, the
existing explicit KVP/DCP consistency checks still apply.

The SM120 outer DeepEP adapter owns expert dispatch and completion. The
FlashInfer MoE plan owns packed local expert weights; the shared expert stays
local and complete. Every participating rank, including an idle one, executes
the same number of transport chunks. The chunk's logical rows and the wire's
communication/layout capacity are distinct. Wire1 Decode retains a fixed
layout capacity across short final chunks; invalid receive rows must not
escape into routing or output.

Transport buffers are prepared before capture and shared only by serial
layers with matching process group, format and dimensions. Runtime imports
for this preparation bypass operator selection because they create persistent
communication resources; operator implementations remain within
`tokenspeed-kernel`.

The optional FlashInfer MoE EP backend replaces routed experts before the CED
boundary. Later layers retain the Elastic path for the short replay rows.
Enable it only on eager disaggregated Prefill with local DP8/EP8 and TP1, static
MXFP4 experts, FlashInfer 0.7.5 and the dependencies required by FlashInfer GIN.
The existing router, routed output scaling and shared expert run in TokenSpeed.
All EP ranks use the same inner chunk bound even when a rank has no local rows.
The backend currently owns communication storage outside the memory-saver
lifecycle. TokenSpeed rejects this combination at startup.

## Precision

W4A8 denotes MXFP4 routed-expert weights with FP8 activations. It does not
specify the Indexer's precision or the shared/dense projections. The baseline
Indexer uses the existing BF16 scoring contract. Native dense FP4 scoring and
FP4 candidate production are independent explicit opt-ins and require their
own numerical and quality qualification.

Install the [SM120 DeepGEMM build][deepgemm] before enabling native FP4.
It exposes the `deep_gemm_sm120` Python namespace and can coexist with the
ordinary DeepGEMM install.

The default mHC projection uses the portable IEEE Triton kernels on SM120.
Ordinary DeepGEMM's mHC prenorm implementation supports architecture families
9 and 10, so its registry capability excludes SM120. The optional
`TOKENSPEED_ENABLE_SM120_MHC_MIXES=1` registers a separate compensated
`tf32x3` Tensor Core projection for coefficient mixing; it retains FP32
weights and requires its own numerical and model qualification. Enabling
that optimization does not change the default precision contract.

The optional NVFP4 checkpoint changes only the declared main routed experts:
G16 E4M3 scales and per-expert calibrated activation/global scales. Native
FP8 dense weights retain their existing format. Fused w1/w3 scalar scales
must agree. Unsupported quantized layers, scale formats and draft-expert
scope are rejected before loading.

MXFP4 Engram stores packed E2M1 codes and G32 UE8M0 scales in the existing
packed host allocation. Lookup decodes gathered rows only, never the resident
table. The MXFP8 direct-to-wkv optimization applies only to MXFP8 storage.
Host-NUMA allocation lifetime and shared-writer ownership retain the common
Engram contract; parallel checkpoint readers copy disjoint complete rows.

## Opt-ins

The launch recipes set these explicitly rather than relying on environment
left by a previous run:

| Variable | Meaning |
| --- | --- |
| `TOKENSPEED_EXPERIMENT_SM120_DEEPEP` | Enable outer SM120 expert communication |
| `TOKENSPEED_SM120_DEEPEP_WIRE` | `elastic_fp8_bf16` or optional `nvfp4_fp8` |
| `TOKENSPEED_SM120_DEEPEP_CAPACITY` | Positive transport chunk bound |
| `TOKENSPEED_SM120_DEEPEP_NICS` | Optional comma-separated NIC names in visible GPU order |
| `TOKENSPEED_EXPERIMENT_SM120_SHARED_OVERLAP` | Explicit shared-expert overlap choice |
| `TOKENSPEED_ENABLE_SM120_PREFILL_INDEXER` | Register SM120 BF16 indexer geometry and exact selector |
| `TOKENSPEED_ENABLE_SM120_PAGED_PREFILL` | Read paged KV directly for eligible single-request Prefill |
| `TOKENSPEED_ENABLE_SM120_NATIVE_FP4_INDEXER` | Optional dense native FP4 scoring |
| `TOKENSPEED_ENABLE_SM120_FP4_CANDIDATE_INDEXER` | Optional FP4 candidate production |
| `TOKENSPEED_SM120_PREFILL_CAKE_ROWS` | Optional routed MegaMoE inner chunk bound for Prefill, in multiples of 128. Zero uses Elastic. |
| `TOKENSPEED_SM120_CAKE_DECODE_MLA` | Enable the FlashInfer mixed-cache Decode kernel |
| `TOKENSPEED_SM120_CAKE_DECODE_MLA_WIDE` | Enable the additional verified row counts with the Decode kernel |
| `TOKENSPEED_EXPERIMENT_SM120_DG_INDEXER` | Optional compact Decode scoring path |
| `TOKENSPEED_ENABLE_SM120_MHC_MIXES` | Optional compensated Tensor Core mHC projection |

These flags do not establish model quality or performance. Operator tests,
full-model measurements and fixed dataset regressions remain separate checks.

## Native 1P1D example

Use one eight-GPU SM120 node for each worker. Set `MODEL` to the same local W4A8
checkpoint on each host, and set `GATEWAY_HOST` to the gateway address reachable
from both workers. Start the gateway first. The example uses the context limit
and per-role parallelism of the native validation run.

```bash
smg launch --pd-disaggregation --backend tokenspeed \
  --prefill "tcp://${GATEWAY_HOST}:31700" --decode "tcp://${GATEWAY_HOST}:31710" \
  --model-path "$MODEL" --tokenizer-path "$MODEL" --host 0.0.0.0 --port 8000 \
  --multimodal-tensor-transport inline --mm-per-request-image-limit 160 \
  --max-payload-size 536870912
```

Run this common setup on both workers, with `WORKER_HOST` set to the worker's
reachable address. Use the NCCL and NVSHMEM interface and device settings for
the host topology.

```bash
export TOKENSPEED_EXPERIMENT_SM120_DEEPEP=1
export TOKENSPEED_SM120_DEEPEP_WIRE=elastic_fp8_bf16
common=(
  --model "$MODEL" --trust-remote-code --dtype bfloat16
  --attention-backend deepseek_v41 --dense-gemm-backend deepgemm
  --moe-backend flashinfer --moe-mxfp4-fp8-activation
  --tensor-parallel-size 1 --data-parallel-size 8 --ep-size 8 --world-size 8
  --query-context-parallel-size 1 --kv-parallel-size 1
  --dense-tp-size 1 --moe-tp-size 1 --attn-head-tp-size 1
  --host "$WORKER_HOST" --data-parallel-address "$GATEWAY_HOST" --zmq-engine-index 0
  --disaggregation-transfer-backend mooncake --disaggregation-layerwise-interval 0
  --max-model-len 135168 --chunked-prefill-size 4224 --max-prefill-tokens 4224
  --engram-host-table --engram-host-table-layout shared --engram-host-table-dir /dev/shm
  --disable-prefill-graph --disable-pdl --force-deterministic-rsag
  --speculative-algorithm DSPARK --speculative-num-draft-tokens 6 --speculative-num-steps 5
)
```

On the Prefill worker, set the MegaMoE row bound to `0` for Elastic or `1024`
to enable MegaMoE. The FP4 flags select the Indexer used for the Pareto.

```bash
export TOKENSPEED_SM120_DEEPEP_CAPACITY=2048
export TOKENSPEED_SM120_PREFILL_CAKE_ROWS=1024
export TOKENSPEED_ENABLE_SM120_PREFILL_INDEXER=1
export TOKENSPEED_ENABLE_SM120_PAGED_PREFILL=1
export TOKENSPEED_ENABLE_SM120_NATIVE_FP4_INDEXER=1
export TOKENSPEED_ENABLE_SM120_FP4_CANDIDATE_INDEXER=1

ts serve --headless "${common[@]}" --disaggregation-mode prefill \
  --dist-init-addr 127.0.0.1:31703 --data-parallel-rpc-port 31700 \
  --disaggregation-bootstrap-port 31720 --gpu-memory-utilization 0.95 \
  --max-num-seqs 32 --enable-prefix-caching
```

On the Decode worker, enable the mixed-cache MLA paths for the verified
capture buckets.

```bash
export TOKENSPEED_SM120_DEEPEP_CAPACITY=128
export TOKENSPEED_EXPERIMENT_SM120_SHARED_OVERLAP=1
export TOKENSPEED_SM120_CAKE_DECODE_MLA=1
export TOKENSPEED_SM120_CAKE_DECODE_MLA_WIDE=1
export TOKENSPEED_EXPERIMENT_SM120_DG_INDEXER=1
export TOKENSPEED_EXPERIMENT_SM120_DEEPSELECT=1

ts serve --headless "${common[@]}" --disaggregation-mode decode \
  --dist-init-addr 127.0.0.1:31713 --data-parallel-rpc-port 31710 \
  --gpu-memory-utilization 0.85 --max-num-seqs 128 --disable-prefix-caching \
  --max-cudagraph-capture-size 8 --cudagraph-capture-sizes 1 2 4 8
```

For a two-node EP16 Decode worker, use DP/EP/world size 16, two nodes with
distinct node ranks, and a shared Decode rendezvous address. The 1P1D accuracy
results below use EP8 Decode and the Decode Pareto uses an independent EP16
replay.

## RTX 6000D measurement

### Prefill

Run the offline one-output queue on TP1/DP8/EP8 with a 126,976-token cached
prefix per rank, random 4,096-token continuations, 128 replay rows, Native FP4
Indexer, and a fixed KV capacity of 2,759,680 tokens per rank. The four load
points activate 1, 2, 4, and 8 ranks. The observer verifies 4,224 physical
rows per active rank and zero Decode rows in each sampled forward. Each point
uses ten consecutive rank-0 completion intervals after warmup and trims the
fastest and slowest two intervals. Throughput counts new tokens, divided by
all eight GPUs. The isolated benchmark checkout relaxes the deployment role
check so the offline driver can instantiate MegaMoE.

| New tokens/GPU/step | Elastic (ms) | MegaMoE (ms) | Elastic tok/s/GPU | MegaMoE tok/s/GPU | Throughput change |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 512 | 621.60 | 539.77 | 824 | 949 | +15.2% |
| 1K | 622.88 | 581.30 | 1,644 | 1,762 | +7.2% |
| 2K | 670.85 | 598.79 | 3,053 | 3,420 | +12.0% |
| 4K | 828.01 | 705.64 | 4,947 | 5,805 | +17.3% |

Both runs passed all 960 formal requests with matching input hashes. The two
backends ran on separate RTX 6000D nodes with matching settings. MegaMoE used
1,024-row inner chunks. A third node reproduced its 4K point at 5,815 tok/s/GPU.

### Decode

Independent two-node TP1/DP16/EP16 replay on 16 RTX 6000D GPUs with
131,072 tokens of history. The driver retained six positions every step.
Equivalent output rates use a fixed acceptance factor of 4.75. Each batch
point contains 100 measured intervals per rank.

| Batch per rank | Slowest rank mean step (ms) | Equivalent output tok/s/GPU |
| ---: | ---: | ---: |
| 1 | 26.37 | 180 |
| 2 | 30.76 | 309 |
| 4 | 35.05 | 542 |
| 8 | 43.98 | 864 |
| 16 | 76.66 | 991 |
| 32 | 141.65 | 1,073 |

### Routed MoE

EP8 with checkpoint layer 8, 2,048 rows per rank, and identical activations
and routes. After warmup, the median over 24 graph replays of the slowest
rank moved from 6.13 to 5.26 ms for uniform routes and from 7.27 to 5.93 ms for
skewed routes. Both backends had 4.3–4.5% relative L2 error on sampled rows
against independently dequantized FP32 expert weights.

### Accuracy

The previous W4A8 run on `224acacb3` used DP8 Prefill and EP16 Decode.
The baseline is its three-run mean. The 1P1D column is one run with EP8
Decode. All 260 request body hashes match the baseline for the same cases.

| Dataset | Existing baseline | 1P1D validation | Difference |
| --- | ---: | ---: | ---: |
| MMLongDoc 50, strict DocQA | 61.25 | 62.45 | +1.20 points |
| MMMU-Pro 210 | 59.84% | 57.62% (121/210) | -2.22 pp |

All 260 requests completed. MMLongDoc had no truncations. MMMU-Pro had
24 truncated responses scored as zero and no unparsed answers.

The focused SM120 runtime suite passed 42 cases, including uniform chunk
bounds with active and idle EP ranks. The attention paths passed 43 GPU
cases on RTX 6000D.
