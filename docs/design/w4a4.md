# FlatQuant W4A4

W4A4 expert checkpoint support belongs beside W8A8 in the runtime. `int4`
denotes symmetric dynamic-token INT4 with required FlatQuant parameters; it
is not weight-only `mxint4`, NVFP4, or the smooth-only INT4 fused-kernel ABI.
GPU quantization schemes and W8A8 arithmetic are unchanged.

The checkpoint owns two BF16 Kronecker matrix pairs and two FP32 clip factors.
For width K, matrix dimensions are the closest ascending factor pair of K.
All parameters must be loaded; missing matrices must not become identity.
The left matrix is transposed once when preparing the native invocation.
Expert TP is one: EP shards complete experts, without splitting either transform.

Weights contain eight signed INT4 values per INT32, least significant nibble
first. With `w4a4_gmm_is_transposed=true`, source and prepared weights are
`[E,N,K/8]`. Otherwise checkpoint `[E,N/8,K]` is transposed at load time to
`[E,K,N/8]`. On 910B, preparation unpacks signed nibbles, merges experts
along the outer NZ column axis and uses `npu_convert_weight_to_int4pack`;
`npu_format_cast(..., customize_dtype=3)` is not supported on this SoC.
Both layouts retain INT4 storage metadata;
the consuming kernel must honor the layout for both GEMMs. Never transpose
an already-NZ tensor as though it were an ordinary contiguous INT32 matrix.
Per-tensor checkpoint scales expand across output channels at load time;
per-channel scales preserve their channel order. Fused dequantization takes
FP32 `[E,N]` scales, not the official GMM UINT64 scale encoding.

Preparation and validation happen outside capture. Execution may only select
a fused kernel that explicitly accepts both transforms, clips, and layouts.
An older smooth-only fused kernel must fail admission, not ignore inputs or
fall back to a split implementation. Weight preprocessing checks the native
ABI before preparing constants; checkpoint support alone is not runnable
end-to-end support.

The matching `fused_mm13_mm2` implementation performs input FlatQuant once
per token, then gathers packed INT4 and its FP32 scale. MM13 accumulates INT32;
Vector applies activation and channel scales and SwiGLU. Both FlatQuant
matrix transforms run on Cube; Vector clips and packs their results.
MM2 consumes that packed result, then dequantizes and
combines routes. Both GEMMs use the explicitly selected NZ orientation. There
is one operator launch, not standalone FlatQuant/GMM launches hidden in a
framework wrapper. MM13 retains two-task input prefetch.

The second transform reuses the input FlatQuant Cube implementation after
MM13 writes a BF16 SwiGLU workspace. MM13, FlatQuant-2, and MM2 are sequential
phases within that kernel, so their L1/L0/UB allocations do not overlap.
Dynamic W4/W8 retains the original MM13/MM2 cross-task overlap. MM13's
weight-scale cache is reloaded each DSQ task after phase-storage reuse;
W8A8's persistent cache is unchanged. This is not a performance-parity claim.

Native admission requires 24 AIC/48 AIV, aligned GEMM widths, and enough UB for
the selected shape. Transform factors must be in [8,128]. Unsupported shapes,
missing parameters, or mismatched ABI fail explicitly. Rank-local expert tests
do not establish full-model checkpoint accuracy or distributed service support.
